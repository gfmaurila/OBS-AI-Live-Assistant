## Regras de leitura

- Requirements definem **o que** o produto deve fazer; Architecture decidirá **como**.
- `CONFIRMED` identifica requisito sustentado pelas fontes aprovadas.
- `ASSUMPTION`, `REQUIRES_RESEARCH`, `REQUIRES_ADR`, `REQUIRES_CLIENT_DECISION`, `OUT_OF_SCOPE_V1` e `FUTURE` preservam incertezas e limites.
- Nomes de providers representam possibilidades conhecidas, não compromisso de implementação.
- Valores numéricos ainda sem evidência permanecem configuráveis ou dependentes de decisão posterior.

Status da fase: **CONCLUÍDO**. Requirements Quality Gate: **PASSED**. Architecture Readiness: **READY**, condicionada às pesquisas, Security Requirements e ADRs identificados.
